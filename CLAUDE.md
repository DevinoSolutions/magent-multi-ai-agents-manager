# magent — agent guide

Open every project in its own terminal, launch an AI agent in it, and auto-tile every window across every monitor. Entry point: `magent = magent.cli:main` (pyproject.toml). User-facing docs live in README.md and `magent docs` (generated config-schema reference); architectural rationale and the known-debt ledger live in DESIGN.md — this file is the terse map for a cold agent session, not a restatement of either.

## Commands

- Setup: `pip install -e ".[dev]"` (uv equivalent: `uv sync --extra dev`; `uv.lock` is committed). One-time: `npm install` to activate the husky pre-commit hook. Sentry error reporting ships in the base install (sentry-sdk is a base dep; there is no `[sentry]` extra) and stays env-gated via `MAGENT_SENTRY_DSN`.
- Quality gate — **must pass before every commit**: `uv run python scripts/check.py` (full, default) or `uv run python scripts/check.py --fast` (pre-commit hook, ~5 seconds). **Full** runs: ruff check + ruff format --check + custom lint (MD001-MD006) + ty strict (src+scripts, plus a second `--python-platform win32` pass scoped to `platform/windows.py`+`hotkey.py`) + compileall + vulture + pytest unit w/ cov. **Fast** runs: ruff + format + custom lint + both ty passes (skips compileall/vulture/pytest). The husky pre-commit hook runs `--fast` automatically; the husky pre-push hook runs the full gate (no `--fast`) as a second line of defense. Pytest enforces a `--cov-fail-under=52` coverage floor (calibrated to the "Lint + Type Check + Coverage" CI job's ubuntu-latest run, not a local Windows box — `platform/windows.py`/`hotkey.py` are 0%-coverable there, pulling total coverage down several points vs. Windows) and `--strict-markers` (an unregistered `@pytest.mark.*` is a hard error, not a silent no-op). CI's `quality` job runs `uv lock --check` then the full gate via `uv sync --extra dev --frozen --python 3.13`; the separate `unit` job runs the OS x Python matrix (3.10–3.14, windows/macos/linux) via plain `pip install -e ".[dev]"`. Two advisory security jobs ride alongside (not in the local gate, by design — see DESIGN.md): a pinned-CLI gitleaks secret scan on every push/PR, and `dependency-audit.yml` running pinned `pip-audit` on dependency changes + a weekly schedule; `.github/dependabot.yml` files weekly update PRs (uv / github-actions / npm).
- Unit tests: `pytest tests/unit/ -q` — last measured 569 passed, 2 skipped on this branch; re-run rather than trusting that count indefinitely.
- Single test: `pytest tests/unit/test_x.py::test_y`.
- e2e locally: `pytest tests/e2e/ -m "e2e and not needs_ssh"`. WARN: a bare `pytest` also collects `tests/platform/` (needs a real display/terminal), the `needs_ssh` e2e tests, and `tests/dist/` (builds a real wheel each session) — CI splits these into separate jobs/legs; don't run bare `pytest` locally and read a clean exit as "the gate passed".
- The `needs_ssh` tier is CI-only by design: `tests/e2e/test_ssh.py` (dry-run pins) + `tests/e2e/test_ssh_real.py` (REAL wire — every test traverses the loopback sshd that `.github/actions/setup-ssh-server` provisions, exporting `MDTEST_SSH_PORT`/`MDTEST_SSH_KEY`/`MDTEST_SSH_HOST` and an `mdssh` alias in the runner's real `~/.ssh/config`). Locally these skip because the env vars are absent — **never install/enable an SSH server on a dev machine to run them**. Tests that seed the ssh user's real HOME (the Windows attach flagship — attach can't inject `--config` remotely) are additionally gated on `GITHUB_ACTIONS=true` / `MDTEST_ALLOW_REAL_HOME=1`. macOS window-over-SSH legs are a loud `::warning` skip (see DESIGN.md known debt).
- dist (packaged-install) locally: `pip install build` (not a dev extra; CI installs it per-job) then `pytest tests/dist/ -m dist` — builds a wheel, installs it into a pristine no-extras venv, and drives the real installed `magent` entry point (proves the exact `pip install` user env; import-sweep catches dev/optional-dep leaks). Window-spawn leg is win32-only and skips elsewhere; wheel build + import sweep + virgin first-run + socket-real serve run on every OS.
- Real-PTY menu tier (`tests/e2e/test_pty_menu.py`, marker `pty`, rides the existing `end-to-end` CI job on all 3 OSes): drives the installed `python -m magent` under a genuine pseudo-terminal — pexpect on POSIX, pywinpty/ConPTY on Windows (`pywinpty>=2.0; sys_platform=='win32'` in the `dev` extra) — via the uniform driver `tests/e2e/_pty.py`, asserting on the plain on-screen text (ANSI stripped; children run `NO_COLOR=1`) and, for first-run, the valid config written to disk. This is the only test of the real `sys.stdin.isatty()` interactive path (`CliRunner` fakes the tty). Locally it runs anywhere pexpect/pywinpty resolve. The same tier also carries `tests/e2e/test_pty_attach_status.py` — the reconnect status line drawn onto a REAL frozen alternate-screen frame (`tests/e2e/_attach_pane.py` is the stand-in TUI + the real `supervise` loop; only `ssh_argv`/`_probe_session`, i.e. the network boundary, are substituted). Its assertions read a GRID, not a string: `tests/e2e/_screen.py` is a small VT model (alt screen, CUP, EL/ED, DECSC/DECRC, scroll counting) replaying the real byte stream, because a pty reports what a child *wrote* and the question is what the terminal *drew*. It is also where the colorama/CUP finding was caught — see DESIGN.md "The status line owns the bottom row". The driver itself is pinned by `tests/e2e/test_pty_driver.py` (same tier, no ssh, all OSes): a silent child and a chatty-but-wrong child must each make `expect`/`wait_exit` raise `PtyTimeout` **within** their deadline, carrying the partial transcript. That is a harness-correctness property, not a nicety — a blocked wait does not fail a test, it burns the job's `timeout-minutes` and GitHub CANCELS the job, discarding every result and diagnostic (it did: a Windows `needs_ssh` leg sat in one test for 13m39s twice running). Two holes caused it and both are closed in `_pty.py`: pywinpty's `read` is an untimed `socket.recv` (Windows reads now go through a daemon reader thread + queue), and `expect` used to `continue` past its own deadline check on any successful read (the clock is now read every iteration). `_pty.Budget` is the other half — a whole-test wall-clock allowance passed to `Pty(budget=...)` that clamps every stage, because per-stage timeouts sum to a worst case nobody chose; every pty tier carries one.
- Alt+V status-line tier (`tests/e2e/test_altv_flash.py`, marker `e2e`, rides the existing `end-to-end` job on all 3 OSes): drives `altv.handle_press` against a REAL `magent serve` (own process, loopback, HOME-redirected tmp, `MAGENT_HOTKEY_SUPERVISOR=0`) whose PATH carries a REAL executable named `psmux` that records every argv it is spawned with. Nothing between the press and the multiplexer is faked, so it pins the phase ORDER, the specific failure reasons, the press-to-bar LATENCY, and that a slow status line delays neither the press nor the upload. The `stalled_paste_fleet` variant makes that same real binary sleep 30s on `send-keys` (the measured production stall) and pins the other half: the press reaches an outcome in ~3s, the narration is `inject-pending` and never a failure, the file is byte-identical on disk, and exactly one paste is attempted. The keyboard hook half stays in the CI-only interaction tier.
- Serve-watchdog tier (`tests/e2e/test_serve_watchdog.py`, marker `e2e`, rides the existing `end-to-end` job on all 3 OSes): drives a REAL detached `magent attention -d --interval 1` (HOME-redirected tmp, fake `psmux` on PATH, bind-0 port, `MAGENT_HOTKEY_SUPERVISOR=0`, supervisor ON with a 3s `MAGENT_UPLOAD_RESPAWN_COOLDOWN_S`) and pins that (1) it starts a real `magent serve` on the configured port when none exists and (2) a DIFFERENT server answers `/health` after the first is killed — plus that the revived server inherited the daemon's env (no keyboard hook), and that `MAGENT_UPLOAD_SUPERVISOR=0` leaves the port dead. Every wait is bounded and the whole test runs under one `_Budget` wall clock (~35s observed, 180s ceiling); teardown kills only the pids it created.
- Shared-log tier (`tests/e2e/test_log_multiprocess.py`, marker `e2e`, rides the existing `end-to-end` job on all 3 OSes): spawns N REAL Python processes that all write the same `~/.magent/logs/<name>.log` through the real `log.get_logger` machinery (HOME fully redirected — `HOME`/`USERPROFILE`/`HOMEDRIVE`/`HOMEPATH`, since `LOG_DIR` is `Path.home()`-derived), released off a shared wall-clock start with a shrunken `maxBytes` so rotation is forced repeatedly mid-burst. Asserts on disk: every record present exactly once, no torn line, no `--- Logging error ---` on any child's stderr, rotation demonstrably happened, and the retained files sat well under capacity (so "missing" can only mean "lost", never "aged out"). Runs anywhere; the Windows behavior is the load-bearing one. It is RED on the stdlib handler.
- Browser-upload tier (`tests/e2e/test_upload_browser.py`, marker `browser`, dedicated `browser-upload` ubuntu job, CI-only, gated on `MDTEST_BROWSER=1`): a real headless Chromium (Playwright — the `browser` extra `["playwright>=1.40"]`, NOT in `dev`, provisioned only by that job via `playwright install --with-deps chromium`) drives the real mobile upload page against a real `magent serve` on loopback and asserts the on-disk upload is byte-identical + the page title/form contract + the Ctrl+V clipboard-paste confirm flow (synthetic ClipboardEvent → staged preview with Send gated on project selection → XHR upload → byte-identical `paste-*.png` on disk). The `stalled_serve` fixture is the three-state half: its `psmux` is a one-line sh wrapper that sleeps past `INJECT_GRACE_S` on `send-keys` only (every other subcommand execs the same real tmux), so `/upload` answers `inject_pending` and the page must show "saved - paste still pending" in the healthy tint — asserted against every class the result surfaces ever took, recorded by an in-page `MutationObserver`, because the page resets the drop zone 2s after an outcome. Locally the module skips cleanly (no `MDTEST_BROWSER`, no Playwright). Honest gap: it symlinks real `tmux` as `psmux` and stands up a real tmux session as the multiplexer shim (Linux has no `psmux` binary) — see DESIGN.md. The `many_serve` fixture is the multi-project half (`_BrowserServe(titles=[...])`, one real tmux session per title): it drives the page's type-to-filter project picker — typing narrows and reorders the pills by the CLI's ranking tiers (prefix > word-boundary > substring > subsequence, ties in config order), arrows walk the highlight, and Enter *and* a tap each select and upload byte-identically. Served-page drift pins live in `tests/unit/test_upload_server.py::TestTheProjectPickerFiltersAsYouType`.
- The `needs_tailscale` tier is CI-only by design (`tests/e2e/test_tailnet_real.py` + the non-required `tailnet` ubuntu job): it joins a REAL ephemeral, tag-scoped Tailscale node (`tailscale/github-action`, SHA-pinned, OAuth via `TS_OAUTH_CLIENT_ID`/`TS_OAUTH_SECRET` + `tag:ci`) and exercises `tailnet.py`'s live `tailscale` probes (`ip4`/`magicdns_host`/`probe`) plus `magent serve`'s Tailscale-facing default bind (`/health` answers on the real Tailscale IP; the LAN wildcard is proven unbound). Gated on `MDTEST_TAILSCALE=1` — locally it skips because the var is absent; **never install/join Tailscale on a dev machine to run it** (same posture as `needs_ssh`). The OAuth secrets don't exist yet: the job detects their absence and skips LOUDLY (`::warning`, job stays green, forks never fail) — once the user adds them it goes fully live with zero code change (one-time setup steps in the job comment). Excluded from the `end-to-end` job's SSH-less run exactly like `needs_ssh`.
- The `monitor_lab` tier is CI-only by design (`tests/platform/test_monitor_lab_tiling.py` + the `monitor_lab` CI job, windows-latest): it INSTALLS the parsec-vdd virtual-display driver to fabricate a mixed-DPI multi-monitor topology, then drives real `--go` tiling across the virtual monitors and asserts each window rect lands in its `compute_grid` cell (physical pixels). Gated on `MDTEST_MONITOR_LAB=1` — locally it skips because the var is absent; **never install the driver / set the var on a dev machine to run it** (same posture as `needs_ssh`). The lab engine is `tests/platform/monitor_lab.py` (stdlib ctypes, win32-only, import-harmless on POSIX). The offline half — `tests/unit/test_monitor_lab_topologies.py` feeding committed golden topologies (`tests/platform/fixtures/topologies/*.json`) into `compute_grid` — runs everywhere in the normal unit gate. Two more CI-only Windows interaction tiers ride in the platform-integration windows leg (same never-on-a-dev-box posture): the `wt_cold` tier (`tests/platform/test_wt_cold_start.py`, gated `MDTEST_WT_COLD=1`) pins the first-ever `wt` launch on the fresh runner against the default settle+retry tiling budget — coldness is guaranteed by CI step ordering, so it must stay the first step that can spawn wt; and the `interaction` tier (`tests/platform/test_real_hotkey.py`, gated `MDTEST_INTERACTION=1`) drives the REAL Alt+V chain — product-spawned listener, real `SendInput` chord, real CF_DIB clipboard, real `serve` + psmux inject — and would stomp a dev machine's clipboard/keystrokes, so never set the var locally. The windows leg also installs pinned psmux (v3.3.6 release zip, sha256-verified, into `%LOCALAPPDATA%\psmux`) so `tests/platform/test_real_psmux.py` (lifecycle + full attach chain in a real wt window) runs instead of skipping. Riding in the same CI job (shared `lab` fixture + driver install via `tests/platform/conftest.py`): the doctor-replay tier — `magent doctor --json` emits monitor topology under a `monitors` key, `tests/platform/doctor_replay.py` plans an achievable lab topology from a bug-report blob, `tests/platform/test_doctor_replay.py` replays committed sample reports (`tests/platform/fixtures/doctor_reports/*.json`) live, and `tests/unit/test_doctor_replay_offline.py` pins the parse/plan/slot math (incl. negative origins) everywhere.
- Real-writer contract tier (`tests/e2e/test_state_sink_contract.py`, marker `node_contract`, rides the existing `end-to-end` job on all 3 OSes — node is preinstalled on every hosted runner, so no CI change): `npm install`s the pinned real agent-state writer package (`ai-agent-notifier@1.0.6` — see `AINS_VERSION`) into a tmp prefix, drives its REAL hook (`src/notify.mjs`) under real node with realistic Claude `Stop`/`Notification`/`SessionStart` events and a fully-redirected HOME, then checks magent's real `agent_state` reader against it. It PINS a headline finding (F-NC-001, since resolved by the in-repo `state_hook.py` writer): the npm package writes ZERO `~/.magent/state/` records (it is a pure notifier; there is no `state-sink.mjs`) — the tier asserts the store stays empty under that package's hook alone and flips RED if the notifier ever grows a conflicting writer. Skips cleanly if node/npm or the npm registry are unavailable; tmp-dir only, never touches real `~/.magent`/`~/.claude`.
- Nightly soak tier (`tests/e2e/test_soak.py`, marker `soak`, CI-only, gated on `MDTEST_SOAK=1`; dedicated `.github/workflows/soak.yml` — `schedule` nightly + `workflow_dispatch`, ubuntu-latest + windows-latest, non-required): drives a REAL `serve --host 127.0.0.1` + REAL detached `attention -d --interval 1` under a sustained churn loop for `MDTEST_SOAK_SECONDS` (default 1500s ≈ 25 min active, ≤45-min job budget) — cycling the full agent-state vocabulary + periodic real POST /upload & /health round-trips — asserting throughout AND at the end: heartbeat mtime keeps advancing (never stale per `log.HEARTBEAT_MAX_AGE`), uploads accepted byte-identical at minute 25 as minute 1, both pids survive, RSS never runs away (stdlib sampling: `/proc` on Linux, ctypes `GetProcessMemoryInfo` on Windows), log rotation stays bounded, TTL sweep spares fresh records. Locally it skips (var absent); **never set `MDTEST_SOAK` on a dev box** — it deliberately runs tens of minutes. Copies `test_daemon_lifecycle`'s HOME-redirect isolation; a no-op `psmux` shim on the child PATH stands in for a real multiplexer so the upload-accept path is exercised (same device as the browser tier's tmux symlink).
- Run: `magent` (interactive menu), `--go` (skip menu, launch+tile), `--dry-run`, `magent config migrate` (stamps `SCHEMA_VERSION` and persists backfilled project colors — `load_config` itself never writes to disk), `magent serve --host <addr>` escape hatch (default bind is loopback + Tailscale IP, never the LAN wildcard; pass `--host 0.0.0.0` to explicitly restore a LAN-wide bind). Attention stack: `magent attention -d` (daemon: title badges + taskbar flash + optional toast/ntfy per `settings.attention` + `MAGENT_NTFY_TOPIC`; heartbeat shows in `status`, stopped by `down --all`) and `magent watch` (live most-urgent-first table; digit key focuses that window). Both read `agent_state` through `attention.AttentionEngine` — states come from the bundled `magent-state-hook` writer (`state_hook.py`), wired into Claude Code's lifecycle hooks by `magent hooks install` (`cli/hooks_cmd.py`; `magent hooks status` inspects wiring + store freshness). Codex feeds the same store via a printed `notify` recipe.
- `magent status` exit codes (`cli/status.py::status_cmd`): 0 healthy, 1 config missing/invalid, 3 degraded (upload server dead; listener stale or **dead**; attention stale/crashed). Click itself exits 2 on usage errors — framework behavior, not this codebase's.
- Alt+V listener lifetime is **owned by `serve`**, not by a one-shot launch/attach spawn: `upload_server._supervise_hotkey` (daemon thread, immediate check then every `HOTKEY_SUPERVISE_INTERVAL_S`) calls `launch.ensure_hotkey_listener`, which — unlike `start_hotkey_listener` — never RE-AIMS a live listener (it re-checks against the listener's own manifest target, so a serve supervisor cannot fight `magent attach`'s remote wiring). `MAGENT_HOTKEY_SUPERVISOR=0` opts out; **every test fixture that starts a real `serve` must set it**, because the listener installs a system-wide keyboard hook that no HOME redirect contains. `status`/`doctor` share one state machine (`cli/status.py::_listener_state`) and one repair string (`LISTENER_REPAIR_HINT`). Rationale: DESIGN.md §2 "The Alt+V listener is supervised, not spawned once".
- `magent serve`'s lifetime is **owned by `magent attention -d`**, one level up from the listener rule above: `cli/attention_cmd._upload_watchdog` hands `run_attention_loop` an `on_tick` hook driving `launch.UploadServerSupervisor` (loopback TCP probe every poll tick; respawn rate bounded by `UPLOAD_RESPAWN_COOLDOWN_S`, 60s, env-overridable via `MAGENT_UPLOAD_RESPAWN_COOLDOWN_S`). The probe+argv+spawn seam is `launch.ensure_upload_server` / `launch.upload_server_argv` — it lives in `launch.py`, not `cli/background.py`, because a src module must not import the cli package (LS-A-001); `cli/background._maybe_start_upload_server` now delegates to it. Two gates: `settings.uploadServer` (a config with the server off is never second-guessed) and `MAGENT_UPLOAD_SUPERVISOR=0`. Like the hotkey one, **that opt-out is a test-isolation law, not a preference**: every fixture that starts a real `attention -d` sets it to 0, or the daemon spawns a real serve no teardown knows the pid of. The pid file is read for the LOG LINE only — `run_server` writes it after the bind, so it can never be the earlier signal and a recycled pid would blind the watchdog. `run_server` names every exit reason and logs a crash at exception level before re-raising (Sentry capture). Rationale: DESIGN.md §2 "The upload server is supervised too".
- Alt+V presses are narrated, not just logged. The press pipeline is `altv.py` (`handle_press`) — platform-neutral on purpose, so the cross-OS e2e tier can drive a press without a keyboard; `hotkey.py` supplies only the win32 capture step. Each press flashes three phases into the project's psmux status line via `/api/flash`: `Alt+V: capturing...` (dispatched BEFORE the clipboard is read), `Alt+V: uploading...`, then the outcome — success included. Failure text is per-outcome (`altv.OUTCOME_REASONS`), never generic. Flashes go through ONE FIFO pump thread (`altv.flash_async`): async so a press never waits on its own progress report, single-threaded so the phases cannot arrive out of order. `altv.ALTV_OUTCOMES` is the closed vocabulary and every member except `not-a-magent-window` has a reason string; both are pinned by `tests/unit/test_altv.py`. A listener-flagged upload (`?project=`) gets NO status-line flash from `upload_server` — one bar, one narrator (pinned both in unit and e2e), and that silence deliberately extends to the deferred paste verdict.
- **The upload reply never waits out the paste.** `psmux.send_keys` is bounded (`SEND_KEYS_TIMEOUT_S`, 20s default, `timeout=` per call; returns False + a WARNING, never hangs or raises) and `upload_server._inject_paste` runs it on a worker, waiting only `INJECT_GRACE_S` (3s) before answering. `/upload` therefore reports THREE paste states, not two: `injected: true`, `inject_pending: true` (still trying — the reply is early, not wrong), or both false (a real refusal). `altv` maps them to `ok` / `inject-pending` / `inject-failed`; `ALTV_SAFE_OUTCOMES` (`ok` + `inject-pending`) are the ones whose image is on disk and therefore keep the healthy tint. The mobile upload page reads all three too (`isPending` in the served JS; `pend` marker class over the `ok` tint, wording mirrored from `altv.OUTCOME_REASONS['inject-pending']` and drift-pinned by `tests/unit/test_upload_server.py::TestThePageReadsAllThreePasteStates`) — `ok:false` is the only failure it shows, and "neither flag" stays the plain "sent" it is (no psmux / inject off is not a failure). Exactly ONE paste attempt is ever made, capped at `INJECT_TIMEOUT_S` (60s) — a retry on a slow-but-live `send-keys` double-pastes. Rationale + the measured 74s false "upload failed": DESIGN.md §2 "The upload reply is not hostage to the paste".
- Logs: rotating files under `~/.magent/logs/<name>.log` via `log.get_logger(name)`; names in use: `"launch"`, `"upload"`, `"hotkey"`, `"platform"`, `"attention"`, `"sentry"` (the last only when a DSN is set but sentry-sdk is missing — a broken install, since the SDK is a base dep). **A log name is shared by several PROCESSES** (`hotkey` by the listener + `serve` + the foreground CLI; `launch` by the CLI + `serve`; `attention` by the daemon + `watch` + any state-store reader; `platform` by everything), so the handler is `log._SharedRotatingFileHandler`, not the stdlib's: it holds no file across records and serializes each one under a cross-process lock on a `<name>.lock` sidecar (msvcrt/flock, same split as `lockfile.py`). The stdlib handler renames the live file to rotate, which on Windows fails `WinError 32` under contention and then loses *every* subsequent record while the file grows unbounded (measured: 272 of 800 lost). Layout is unchanged — `<name>.log` + `<name>.log.N` — and the sidecar is `.lock` precisely so `glob("<name>.log*")` consumers (the soak tier, a shell) never see it. Cost: ~235µs/record vs ~13µs. Proof: `tests/e2e/test_log_multiprocess.py` (marker `e2e`, all OSes, N real writer processes). Rationale: DESIGN.md §2 "One log file, many processes".

## Architecture

- `cli/__init__.py` is a ~24-line registration hub: imports every command module (running their `@main.command` decorators) and re-exports the names tests/external code reach via `magent.cli.<name>`. `cli/app.py` holds the `main` click group alone, with no top-level imports of sibling command modules, so every command module can `from magent.cli.app import main` without a cycle; the no-subcommand interactive path re-imports its handlers in-body as a documented cycle-break.
- `launch.py::run_magent` is a phase pipeline: `_prepare_grid` → `_select_projects` → `_launch_projects` (per-project dispatch to `_dispatch_ide_project`/`_dispatch_cli_agent_project`) → `_start_psmux_and_upload` → `_tile_targets` (delegates to `tiling.place_windows`). The shell owns the exit code; phases return data.
- `platform/__init__.py`: `Platform` ABC + `get_platform()`. `supports_psmux()`/`supports_hotkey()` default False; `attach_psmux`/`launch_psmux_session` default to `NotImplementedError`. Only `platform/windows.py::WindowsPlatform` overrides those; `macos.py`/`linux.py` implement the abstract methods and take the ABC defaults for the rest.
- `sessions/__init__.py`: the `AGENT_TOOLS` registry (`AgentTool` dataclass: `session_ids`/`resume_command`/`fresh_command`/`happy`), one `sessions/<tool>.py` per deeply-integrated CLI agent (today: `claude.py`, `codex.py`); also the IDE mirror `IDE_COMMANDS`/`IDE_TOOLS` + `is_ide_tool()`/`ide_command()` — no hand-written `('code','vscode','cursor')` tuples anywhere in `src/`. `build_start_command(tool, base_cmd, project_dir)` is the one function every command-build site routes through: it drops an *implicit* resume flag (`claude --continue`) when `project_dir` has no stored session, because that command errors out and leaves a dead pane in a brand-new project directory. Only a positively-determined "no session here" rewrites anything (an explicit `--resume <id>`, a per-window `command` override, a remote project — callers pass `project_dir=None` — and a probe that errors are all left byte-for-byte); a shell-level `|| claude` fallback is forbidden. Rationale + the corrupt-session-file posture: DESIGN.md §2.
- `config.py`: `SCHEMA_VERSION`, `DEFAULT_TOOLS`, the typed dataclasses, pure `load_config` (validates + warns, never writes), `default_config`/`settings_to_dict` (the one envelope factory every generator shares), and `migrate_config_file` (the only function in this module that writes to disk). A project's `windows` field is `list[WindowConfig] | None` (SCHEMA_VERSION 3) — per-window `name`/`tool`/`command` overrides; the legacy `int` / `list[str]` forms still parse and are normalized by `migrate_config_file`. `cli/config_editor.py` hosts the interactive editor (`_config_menu`) and every `config <subcommand>`, including `migrate`.
- `env.py`: the **only module that touches process env** (enforced by TID251 os.environ/os.getenv ban). `MagentEnv(BaseSettings)`: validated MAGENT_* env vars (closed schema, `extra="forbid"`). Dotenv is read from `env.ENV_FILE` (`~/.magent/.env`) **only — never the CWD's `.env`** (magent launches from arbitrary project dirs; their `.env` files must not fail startup). `validation_error_items` is the one env-error formatter (app.py + doctor share it; extra keys report under their raw names, no fabricated MAGENT_ prefix). Host-env accessors (`config_base`, `vscode_storage_base`, `editor_command`, `appdata_dir`, `xdg_config_home`, `localappdata_dir`) for OS-convention variables. `.env.example` drift-pinned by `test_env_schema.py`. `spawn_child_env()` is the **one seam every agent-hosting spawn routes through** — psmux `new-session` (via `psmux.child_env`), the platform backends' `launch_terminal`/`launch_vscode`, and `hotkey.py`'s F2 editor open. It strips three families: the psmux/tmux nesting markers (with the `*_TMPDIR` carve-out), the launching agent harness's session markers (`SCRUBBED_INHERITED_VARS` — `CLAUDECODE`/`CLAUDE_PID`/`CLAUDE_CODE_CHILD_SESSION`/`_SESSION_ID`/`_ENTRYPOINT`, an exact list and deliberately NOT the whole `CLAUDE_CODE_*` namespace, which is mostly credentials and user config), and the launcher's colour overrides (`NO_COLOR`/`FORCE_COLOR`/`CLICOLOR`/`CLICOLOR_FORCE`). `TERM` is never touched in either direction. psmux CONTROL/PROBE commands and the user-facing `attach` client keep the plain inherited environment on purpose.
- `sentry.py`: env-gated Sentry wiring (`MAGENT_SENTRY_DSN`, default off); sentry-sdk is a base dependency so a set DSN always works on a healthy install. Errors-only, no PII, logging integration at ERROR level, atexit flush. Zero imports when DSN unset (the SDK loads lazily inside `init_sentry`). DSN set but sentry-sdk missing = broken install; still quiet degradation: a rotating-log warning (never a per-command stderr nag) + a `sentry` check in `magent doctor` carrying the repair hint `pip install --force-reinstall magent-multi-ai-agents-manager`.
- Leaves with no dependency on the cli package: `paths.py` (`find_config`), `style.py` (`style = click.style`), `titles.py` (`MAGENT_TITLE_PREFIX`), `tiling.py` (`place_windows`, shared by launch-path and attach-path tiling), `log.py` (`get_logger` + heartbeat helpers), `grid.py` (`compute_grid`), `tailnet.py` (`ip4`/`magicdns_host`/`probe` — the only module that shells out to `tailscale`), `procs.py` (`pid_alive` — the one pid-liveness check), `psmux.py` (single owner of every psmux subprocess interaction; imports only `magent.log` at module level), `icons.py` (icon/PNG rendering — pure stdlib), `lockfile.py` (the exclusive-lock guard), `state_hook.py` (the `magent-state-hook` console script — the in-repo lifecycle writer feeding `agent_state`; stdlib + `agent_state` only, and deliberately its own entry point so per-turn hook subprocesses skip the cli registration hub's import cost), `attach_client.py` (the `magent-attach-client` console script — the reconnecting ssh supervisor every `magent attach` pane runs instead of a bare ssh; imports `magent.style` only, its own entry point for the same startup-cost reason, and the single owner of both `SSH_KEEPALIVE_OPTS` and `remote_attach_command` so the pane's real command can't drift from the `-L <sid> attach` marker `cli/attach.py` scans for).
- `upload_server.py` imports `launch`, `log`, `paths`, `platform` at top level; the real invariant (LS-A-001) is narrower than "depends on paths only" — it never imports the **cli package**, because `cli/__init__` imports every command module for registration and a reverse import would cycle.
- `hotkey.py` raises `ImportError` at import time off win32 (by design); every caller imports it lazily behind a `supports_hotkey()` check. The Alt+V *pipeline* deliberately does not live there: `altv.py` (a leaf over `log` + `sessions`) owns `handle_press`, `upload_image`, the flash pump and the outcome vocabulary, so everything downstream of "the chord was ours" is importable — and testable — on every OS.

## Conventions in force

- Adding a new deeply-integrated agent tool = one new `sessions/<tool>.py` + one `AGENT_TOOLS` entry, with no dispatcher change required — proven by `tests/unit/test_tool_registry.py::TestOneEditExtensionProof::test_adding_a_tool_is_one_dict_entry`. A plain command tool (no session resume) is just a `config.DEFAULT_TOOLS` entry.
- `magent.config.example.json` is drift-pinned to the config factory (`tests/unit/test_config_factory.py::TestExampleConfigMatchesFactory`): any change to `DEFAULT_TOOLS` or a `Settings` default must update the example file in the same commit, or the gate goes red.
- Adding a new platform capability = a default on the `Platform` ABC (a False-returning probe, or a `NotImplementedError` body) plus per-OS overrides; gate call sites with `supports_*()`, never a bare `sys.platform` check in business logic. (The handful of remaining `sys.platform` branches — e.g. `cli/ui.py::_open_in_editor`'s editor-command selection — are genuinely OS-behavioral, not capability gates, and are correctly left alone.)
- Subsystem modules (`launch.py`, etc.) return ints or raise; `sys.exit()` decisions live only in the `cli/` command shells.
- Import policy inside `cli/` command modules: stdlib + leaf imports at top; heavy subsystems (`launch`, `upload_server`, `discover`, `agent_state`, and the platform backends via `get_platform()`) are imported in-body with a one-line why-comment — grep `heavy subsystem: in-body per policy` to find every site. Reason: the registration hub imports every command module eagerly, so a top-level heavy import would make `magent --help` pay that subsystem's startup cost. (`hotkey` imports must stay in-body for a second reason: it raises `ImportError` off-Windows.)
- **Tests never touch the real `~/.magent`.** `tests/conftest.py::_isolate_magent_home` (autouse, every tier except `tests/platform/`) redirects the WHOLE home family — `HOME` **plus `USERPROFILE`/`HOMEDRIVE`/`HOMEPATH`**, because `Path.home()` reads USERPROFILE on Windows and a HOME-only redirect is a silent no-op exactly on the box with a live fleet to damage — so every call-time `Path.home()` (`lockfile.exclusive_lock` is one) and every child process (they inherit `os.environ`) lands in tmp. The `~/.magent` constants magent binds at IMPORT time (`cli/attach._LAST_HOST_FILE`, `upload_server._UPLOAD_DIR`, `hotkey._PID_PATH`, …) are too late for an env redirect and are listed in `_IMPORT_BOUND_PATHS`; a new one added to `src/` is caught automatically by the tripwire, not by memory. That tripwire is two deterministic per-test guards (dev-machine only, off on CI): **A** — `~` still resolves into tmp and no `magent.*` module attribute is a Path under the real `~/.magent` or `~/.claude`; **B** — a `subprocess` spawned with an explicit `env=` aiming HOME/USERPROFILE at the real home fails BEFORE the child is created. A session-scoped observer additionally reports (never fails — a live fleet churns those files on its own) if the real `~/.magent` changed across the run. `@pytest.mark.real_home` is the opt-out and today has exactly one user, `tests/e2e/test_ssh_real.py`, which drives magent over loopback ssh as the same user and therefore must keep the runner's own home. Pins: `tests/unit/test_home_isolation.py`. Why this is a law and not hygiene: a leaking test does not fail — it stopped this machine's real Alt+V listener and hung 124s forwarding `magent down` over ssh to the recorded last-attach host, with a green suite.
- Tests: JSON-body assertions read `result.stdout`, never `result.output` — Click 8.4's `CliRunner` merges stdout+stderr into `.output`, so a stderr diagnostic (e.g. the config version warning) can silently corrupt `json.loads(result.output)` (NF-S3-002). Characterization/pin tests are written and green BEFORE the refactor they pin, not after. Shared fixtures `runner`/`fake_platform` and the `FakePlatform` test double live in `tests/conftest.py`; CLI tests pass `--config <tmp_path>` rather than monkeypatching the config location.
- `style(...)` comes from `magent.style`; there is no local `S = click.style` anywhere in the repo — the historical alias was renamed out repo-wide. Enforced by TID251 `click.style` ban.
- `typing.Any` is banned repo-wide (TID251 + ANN401). Use `object` + `isinstance` narrowing. Zero `Any` annotations in `src/`.
- `os.environ` / `os.getenv` are banned outside `env.py` (TID251). All env access goes through `magent.env` accessors.
- Remote attach panes are supervised: `cli/attach.py::_spawn_windows` runs `magent-attach-client` (resolved off PATH by `_attach_client_exe`, degrading to bare ssh with one warning) which redials on ssh exit 255, stops on exit 0 (deliberate detach) and on any other code (the connection worked, the remote command failed — retrying would hot-loop sshd). `--no-reconnect` restores the bare-ssh pane; `--no-mux` is never supervised by design. Corpse detection is coupled to this: the supervisor's argv must keep carrying the `-L <sid> attach` marker (that's why `--remote` is passed explicitly) and `_CLIENT_PROCESS_NAMES` must keep listing `magent-attach-client.exe`, or a pane mid-backoff gets closed as a corpse. Full rationale in DESIGN.md §2.
- "Which psmux sessions are live" has exactly ONE answer: `psmux.live_sessions` (fan-out `has-session -t` + one retry of the misses — probes flap under load, and a dropped probe silently HIDES a live session). `psmux_status` (status/down/menu), the session picker's sweep and `discover_sessions` all call it; never write a fourth sweep. The bring-up creation verify (`psmux._missing_sessions`) is the one deliberate exception and documents why. Shutdown is the other half: `psmux.stop_sessions` (probe → kill → settle → re-probe → re-kill survivors → re-probe) returns `(stopped, still_running)` and is what `down`/`_menu_down` report from — never `kill_servers`, which is attempt-only and cannot say what stopped. `down --all` kills every CONFIGURED eligible session in scope, not the liveness snapshot; only the local-vs-remote decision reads live sessions. Rationale: DESIGN.md §2 "One liveness enumeration, and a shutdown that verifies".
- Window titles follow the grammar in `titles.py` — `magent:` prefix + optional `[!]`/`[x]`/`[+]` state badge + name. Producers call `titles.make_title` (launch-path terminals, psmux attach, `cli/attach.py`); consumers call `titles.parse_title` (`hotkey.py::project_from_title`, tiling's `magent-name` placement mode). Never hand-build or hand-parse a `magent:` string; there are no `f"magent:` literals anywhere in `src/`. psmux *session names* stay unprefixed — the grammar applies only at the window-title boundary.
- The title is magent's, not the app's: every `wt` argv literal must carry `--suppressApplicationTitle` **inside the list next to the `"wt"` token** (not `args.append`-ed later) — enforced by lint rule MD006, because a title an agent rewrote out of the grammar removes the window from tiling, attach dedupe, corpse pairing and the hotkey all at once. POSIX equivalents where they exist: kitty's `--title` is already permanent, alacritty `-o window.dynamic_title=false`, xterm `-xrm XTerm*allowTitleOps:false`; gnome-terminal/konsole/Terminal.app/iTerm have none (ledger item). `attention.BadgeRenderer` repairs a stomped title on the next tick by remembering windows *by handle* — Windows only, daemon only. Rationale: DESIGN.md §2 "Window titles are magent's, not the app's".
- Interactive list selection has exactly ONE component: `cli/picker.py` (deterministic stdlib ranking — prefix > word-boundary > substring > subsequence, ties by original order; `PickerState` as a pure key-driven state machine; one `paint()` both input modes render through). Raw-key mode is gated on `picker.raw_mode_available()` (the same `sys.stdin.isatty()` check), so every caller keeps its line-based `click.prompt` verbatim off a tty — and with an EMPTY query nothing filters or highlights, so digit shortcuts and the bare-Enter default are byte-for-byte today's. Filter mode starts only on a query that is neither all-digits nor one of the caller's single-key `commands`. Used by `cli/menu.py` (menu + group submenu) and `cli/session_picker.py`; `magent watch`'s digit-focus poll is deliberately NOT this. Pins: `tests/unit/test_picker.py`, `tests/unit/test_menu.py`, `tests/e2e/test_pty_picker.py` (marker `pty`).
- Raw-dict config I/O (round-trips unknown/unmodeled keys) lives only in `cli/config_io.py` (`_load_raw_config`/`_save_raw_config`, used by the interactive editor). Every CLI call site loads typed config through `config_io._load_config_or_exit`; its `as_json=True` mode emits a `{"ok": false, "error": ...}` envelope on stdout — adopted by both `status --json` and `up --json` — instead of the plain-text stderr `Error:` line (NF-S3-005; the former `up_cmd` raw-loader exception is gone).
- `agent_state.py` record schema (`{state, ts, cwd, session_id}`) is pinned by `tests/unit/test_agent_state.py::TestSchemaContract` — any change to `write_state`'s payload shape breaks that test before it can break writers/readers out of lockstep. On a deliberate schema change: bump `RECORD_VERSION`, update the contract test, and update any external writer in lockstep. The store's writer is in-repo since feat/state-hook (F-NC-001 resolved — see DESIGN.md ledger): `state_hook.py` (`magent-state-hook`), driven by Claude Code lifecycle hooks that `magent hooks install` wires (UserPromptSubmit→working, PostToolUse→working refresh throttled by `REFRESH_S`, Stop→done **only when the payload's `background_tasks` ledger is drained** — a Stop whose ledger still lists a running subagent/shell entry writes working instead, because Stop means "turn ended", not "work finished", and the harness's re-invocation on background completion guarantees a later drained Stop; unknown entry shapes count as running, Notification→needs-input except the "waiting for your input" idle nag, SessionStart→idle, SessionEnd→clear; Codex notify agent-turn-complete→done). `tests/e2e/test_state_sink_contract.py` (marker `node_contract`) still drives the real published `ai-agent-notifier@1.0.6` under node and pins that it writes ZERO `~/.magent/state/` records — it is a pure notifier; if it ever starts writing records that's a conflicting-writer signal, not a missing-writer one.
- Commit style is conventional (`feat(scope): ...`, `fix`, `refactor`, `test`, `chore`, `ci`, `docs`) — check `git log --oneline` for the pattern in force.

## Gotchas

- This machine's shell hook (`rtk`) filters shell output; if a result looks surprising, re-run via `rtk proxy <cmd>` for the raw output — it has been observed to mislabel a pytest `1 xfailed` as `1 failed`.
- A file literally named `nul` reappears at the repo root from `> nul` redirects under Git Bash on Windows. Delete it; never commit it (same for the untracked `vscode_debug.txt`).
- Click 8.3 vs 8.4 render a bare `--help` usage line differently (`[COMMAND]` bracketed vs not, for `invoke_without_command=True` groups). `tests/unit/test_cli_structure.py::_normalize_help` normalizes exactly that one substring so the help-snapshot pins pass under either installed version.
- ty is pinned to `ty==0.0.72` (pre-1.0; Dependabot moves the pin, CI's full gate proves each bump). The `isinstance(x, dict)`/`isinstance(x, list)` narrowing false positives are **fixed** as of 0.0.72 — the canary fired on that bump (26 `unused-ignore-comment` warnings) and all 26 suppressions were deleted: the narrowing ones in `config.py`, `cli/config_io.py`, `cli/attach.py`, `cli/hooks_cmd.py`, plus `env.py`'s pydantic-settings `_env_file` `unknown-argument`. No new suppression class replaced them. Exactly three `# ty: ignore` comments remain in `src/` and are still load-bearing: the two optional-dep `unresolved-import`s (`winotify` in `attention.py`, `qrcode` in `cli/ui.py`) and `upload_server.py`'s `invalid-method-override`. The canary cuts both ways and stays the rule for every future bump: the gate runs `ty check … --error-on-warning`, so a suppression a new ty made redundant fails as `unused-ignore-comment` (delete it), and a regressed narrowing fails as a real error.
- vulture's `ignore_names` whitelist (pyproject.toml) documents 4 framework-required parameters; add new entries only with a trailing reason comment. Dead code = delete it, don't whitelist it.
- The runtime dotenv lives at `~/.magent/.env` (`env.ENV_FILE`) — a repo-root `.env` is inert (and still gitignored if one appears). `.env.example` is committed and drift-pinned to `MagentEnv` fields by `test_env_schema.py`. A new env var without an `.env.example` update = red gate.
- A config file with no `version` field (or an old one) prints a stderr warning on every load until `magent config migrate` is run; `load_config` itself never writes.
- `qrcode` (used by `cli/ui.py::_print_qr` for `magent mobile`) is an optional dependency: imported in a try/except with an install tip. This is deliberate — don't "declare" it as a missing dependency.
- `ruff format` was applied repo-wide as one isolated `style:` commit; its SHA is recorded in `.git-blame-ignore-revs`. Run `git config blame.ignoreRevsFile .git-blame-ignore-revs` once so local `git blame` skips it (GitHub honors the file automatically). `ruff format --check` is a gate step, so formatting stays enforced.
- ISC004 (implicit string concat inside a collection/argument list) fires even though `ISC` is not in `[tool.ruff.lint] select` — ruff 0.16 made it default-on, and a `select` list does not switch it off. Every hit in this repo is a deliberate multi-line message/argv string, so the fix is always explicit parentheses around the pieces (`--select ISC004 --fix --unsafe-fixes` writes them, then `ruff format`), never a comma.
