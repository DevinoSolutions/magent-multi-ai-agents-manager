# Nodes Sub-plan L: the local session snapshot (serve writes it, the picker paints from it)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The F1 picker stops sweeping every psmux socket on every paint. Today `cli/session_picker.py::_run_sessions_picker` calls `psmux.live_sessions(candidates)` on every redraw: once when it opens and again every time an attach returns. That call is a fan-out `has-session -t` per configured session with an unbounded wait, measured at about 19 s for 46 sockets on a loaded host. A phone running `magent sessions` over ssh is a fresh process each time, so only a file can help it. After L:
- `magent serve` sweeps every 10 s on its own thread and writes the live names to `~/.magent/nodes/local/sessions.json`, in E's `{ts, sessions}` shape;
- the picker paints from that file while it is at most 20 s old, and makes zero `live_sessions` calls on that paint;
- it sweeps live when the file is missing or stale (with one dim hint naming `magent serve`), when the user presses `r`, and on the paint after an attach failed;
- "No active psmux sessions" is only ever said after a live sweep.

**Architecture:**
- **One writer.** `upload_server._refresh_sessions(now)` is the one sweep. It runs `psmux.discover_sessions` (so still `psmux.live_sessions`) under `_sessions_lock`, refreshes `UploadHandler.cached_sessions`, and writes the snapshot with `nodes.write_json_atomic`. It is called by:
  - the daemon thread `_supervise_session_snapshot`, which `run_server` starts;
  - `UploadHandler._sessions`, whose TTL fallback stays for handlers built without `run_server`.
- **One reader.** `cli/session_picker.py::_list_sessions` reads the file with `nodes.read_sessions(NODE_LOCAL)` plus `nodes.sessions_stale`, and filters it to its own config's candidates. A source test pins it as the only reader, and serve as the only writer.
- **Everything else stays live.** `status`, `down`, the menu and `sessions --json` keep calling `live_sessions`, because they decide kills and report truth.

**Tech Stack:** Python 3.10+ stdlib (`threading`, `json`, `dataclasses`, `ast` in one test) and click. No new dependencies and no new env var.

- **DECISION-20 rule 1.** `config.NODE_LOCAL = "local"` joins `_RESERVED_NICKS` (Task 2). The file is `nodes.sessions_path(config.NODE_LOCAL)`. It uses E's `NodeSessions` shape, written by `nodes.write_json_atomic` and read by `nodes.read_sessions` plus `nodes.sessions_stale`.
- **Rule 2.** There is ONE writer:
  - `upload_server._supervise_session_snapshot` on a daemon thread off `run_server`, with `SESSION_SNAPSHOT_INTERVAL_S = 10.0`;
  - it calls `_refresh_sessions()` under `_sessions_lock`;
  - `_sessions()` keeps its TTL fallback;
  - the sweep stays `psmux.discover_sessions`, which is `psmux.live_sessions` over the configured candidates. It is a cache of that call, never a fourth sweep.
- **Rule 3.** The picker paints from the snapshot while `not nodes.sessions_stale(snap, pull_interval_s=SESSION_SNAPSHOT_INTERVAL_S, now=...)`:
  - the header reads `(snapshot <n>s ago)` in place of `(synced with desktop)`, or `(live)` after a sweep;
  - `r` forces a live sweep;
  - a failed attach forces one on the next paint;
  - a missing or stale file means a live sweep plus ONE dim `magent serve` hint;
  - the direct-name attach stays config-resolved and sweep-free;
  - "No active psmux sessions" only follows a live answer.
- **Rule 4.** Nobody else reads the local snapshot. `tests/unit/test_session_snapshot_readers.py` pins the picker as the only `read_sessions(NODE_LOCAL)` site in `src/`, and serve as the only `sessions_path(NODE_LOCAL)` site.
- **Rule 5.** No new env var. The e2e leg sets the existing pins, including E's `MAGENT_NODE_SYNC=0`.
- **Rule 6.** `node_sync` and `MAGENT_NODE_SYNC` are not touched.
- **Latency target.** With a fresh snapshot the first paint makes ZERO `live_sessions` calls. Two tests pin it:
  - one with a fake sweep that sleeps 2 s, asserting the paint is faster than one sweep;
  - one with a fake sweep that raises if called.

## Additive interfaces (DECISION-20 names are untouched)

| Where | Addition | Why |
|---|---|---|
| `upload_server._refresh_sessions(now: float \| None = None) -> list[dict[str, object]]` | `now` is optional; None stamps the moment the sweep RETURNED | A sweep can take about 19 s. A start stamp would make a just-written snapshot look nearly stale (the picker's window is 20 s). Tests pass a fixed `now`. |
| `upload_server._sessions_lock` | `threading.Lock()` becomes `threading.RLock()` | `_sessions()` re-checks freshness under the lock and then calls `_refresh_sessions()`, which takes it again. |
| `UploadHandler._sessions` | a lock-free fast path when the cache is fresh | A request must not queue behind the supervisor's sweep that is already in flight. `cached_sessions` is assigned before `sessions_ts`, so a fresh stamp always comes with its list. |
| `upload_server._snapshot_write_failing` | `threading.Event()` (DECISION-21: no module `global`, no `PLW0603` noqa) | A full disk or a locked file is ONE warning, plus one "writing again" line on recovery, not one every 10 s. The cache is still refreshed. |
| `_supervise_session_snapshot` | cadence is measured start to start; a failure streak logs one exception | A start-to-end pause would push every cycle of a slow sweep past the 20 s window. `log.exception` every 10 s would flood Sentry (errors-only). |
| `session_picker._attach_session(...) -> bool` | True on a clean attach, False after both attempts failed | Rule 3's "a failed attach forces a live sweep" needs the outcome. `cli/status.py::_open_session` ignores the value and is unchanged. |
| `session_picker._Listing`, `_list_sessions(candidates, sweep, *, live, interval_s, now=None)`, `_source_label(age_s)`, `_SERVE_HINT` | the reader | One function decides where a paint's list comes from, and is unit-testable without the loop. |
| `session_picker._read_choice(rows, upload_url, *, source="(live)", hint=None)` | keyword-only header inputs | The raw-key picker clears and repaints the header on every keystroke, so the source label and the hint must live in the header. |
| `session_picker._session_rows` | an `r` row, `Refresh (live sweep)`, between the sessions and Back | The key is discoverable, and a tap or arrow can select it. |

    - `live`: what the fake `psmux.live_sessions` answers.

    - `attach_ok`: what each attach reports (a bool, or a list or tuple
      consumed in order).

    - `sweep_s`: makes the fake sweep as slow as a loaded host.
    - `sweep_raises`: turns any sweep into a test failure. The sweep is still

      that no `except Exception` in the picker can swallow -- so a pin on
      `run.events` can tell "never swept" from "swept and the error was eaten".

    Running out of script is a failure, never a quiet default: a paint past
    the last answer, or an attach past the last outcome, fails the test with
    the events so far.

    Each paint records its row labels and its header inputs."""

    def _run(
        configured,
        live,

        attach_ok=True,
        focus=None,
        name=None,
        sweep_s=0.0,
        sweep_raises=False,

        replies = iter(answers)
        focus_once = iter([focus])

            run.events.append("sweep")

                    f"painted past the {len(answers)} scripted answers;"

def _attach_session(psmux_bin: str, target: str, reset: Callable[[], None]) -> bool:
    """Attach to a session; surface and retry a failed attach.

    True when an attach ended cleanly (exit 0), False when both attempts
    failed. The picker reads False as "the row it offered may be a session
    that has died" and sweeps live on its next paint. `status`'s session menu
    ignores the value.

    The old flow cleared the screen the moment the attach client returned, so
    a failure (e.g. the client losing a resource race on an overloaded host)
    was invisible -- the picker appeared to 'process' the choice and silently
    bounce back to the menu."""
    rc = 0
    for attempt in (1, 2):
        _set_picker_attached(target)
        try:
            rc = subprocess.call([psmux_bin, "-L", target, "attach"])
        finally:
            _set_picker_attached(None)
            reset()
        if rc == 0:
            return True
        if attempt == 1:
            click.echo(
                f"  {style('!', fg='yellow')} attach to {target} exited {rc} -- retrying..."
            )
            time.sleep(1)
    click.echo(
        f"  {style('x', fg='red')} attach to {target} failed twice (exit {rc})."
        f" {style('The host may be overloaded -- try again in a moment.', dim=True)}"
    )
    time.sleep(2)
    return False

# One sweep feeds the phone page's cache AND ~/.magent/nodes/local/sessions.json,

# Event, not a module global: set/clear/is_set need no `global` statement, and

def _refresh_sessions(now: float | None = None) -> list[dict[str, object]]:
    """Sweep once; refresh the request cache and the local session snapshot.

    The sweep is ``psmux.discover_sessions`` -- ``psmux.live_sessions`` over the
    configured candidates, the one liveness enumeration -- so the snapshot is a
    cache OF that call, never a second opinion. ``now`` stamps both; left at
    None it is the moment the sweep RETURNED, because a sweep can take ~19 s on
    a loaded host and a start stamp would make a just-written snapshot look
    nearly stale to the picker.

    A failed discovery raises and changes nothing: the old cache and the old
    file both stay. A failed WRITE never costs the cache: it is logged once per
    failure streak and the sweep's answer is still returned.

        sessions = _discover_sessions(UploadHandler.config_path)
        stamp = time.time() if now is None else now
        # List before stamp: UploadHandler._sessions reads the stamp first,
        # lock-free, so a fresh stamp must never be seen with the old list.
        UploadHandler.cached_sessions = sessions
        UploadHandler.sessions_ts = stamp
        path = nodes.sessions_path(NODE_LOCAL)
        names = list(dict.fromkeys(_sid(s) for s in sessions))
        try:
            nodes.write_json_atomic(path, {"ts": stamp, "sessions": names})
        except OSError as exc:
            if not _snapshot_write_failing.is_set():
                get_logger("upload").warning(
                    "session snapshot: cannot write %s (%s)", path, exc
                )
            _snapshot_write_failing.set()
        else:
            if _snapshot_write_failing.is_set():
                get_logger("upload").info("session snapshot: writing %s again", path)
            _snapshot_write_failing.clear()
        return sessions

def _await_snapshot(
    path: Path,
    proc: subprocess.Popen[str],
    *,
    until: float,
    newer_than: float | None = None,
) -> dict[str, object] | None:
    """The snapshot once it exists (and is newer than ``newer_than``), or None
    at ``until`` or when serve has exited. A parse error is NOT swallowed: the
    write is atomic, so a torn file is a product bug and must say so."""
    while time.monotonic() < until:
        if proc.poll() is not None:
            return None
        try:
            data = json.loads(path.read_text(encoding="utf-8"))
        except OSError:  # not written yet, or mid-os.replace on Windows
            data = None
        if isinstance(data, dict) and (newer_than is None or data["ts"] > newer_than):
            return data
        time.sleep(0.2)
    return None

def _supervise_session_snapshot(
    stop_event: threading.Event, interval: float = SESSION_SNAPSHOT_INTERVAL_S
) -> None:
    """Keep the local session snapshot fresh for as long as serve runs.

    Runs on a daemon thread off ``run_server``: one ``_refresh_sessions`` right
    away (a picker opened a second after serve starts should already find a
    file), then one every ``interval`` measured START to start, so a slow sweep
    does not stretch the cadence -- the picker calls a snapshot stale after two
    intervals, and a start-to-end pause would push a 15 s sweep past that on
    every cycle. A failed sweep is ONE exception-level line (Sentry) per
    failure streak and another try next interval; nothing here may take down
    the server it rides on.
    """
    log = get_logger("upload")
    failing = False
    while True:
        started = time.monotonic()
        try:
            _refresh_sessions()
        except Exception:
            if not failing:
                log.exception("session snapshot: sweep failed")
            failing = True
        else:
            if failing:
                log.info("session snapshot: sweeping again")
            failing = False
        if stop_event.wait(max(0.0, interval - (time.monotonic() - started))):
            return

"""Only the session picker reads the local session snapshot; only serve writes it.

DECISION-20 rule 4. The snapshot (~/.magent/nodes/local/sessions.json) can be
up to 20 s behind the truth. That is fine for a list you pick from, and wrong
for anything that decides a kill or reports state: `status`, `down`, the menu
and `sessions --json` stay on `psmux.live_sessions`. A second reader would be a
second answer to "which sessions are live", the exact drift the one-sweep law
exists to prevent.

The scan is an AST walk over src/, so a call inside a function body counts.
Its blind spot is the nick passed through a variable (`nick = NODE_LOCAL;
read_sessions(nick)`); test_the_scan_is_not_vacuous pins every direct spelling.
"""

from __future__ import annotations

import ast
from pathlib import Path

import magent

_SRC = Path(magent.__file__).resolve().parent


def _is_local_nick(node: ast.expr) -> bool:
    """`NODE_LOCAL`, `config.NODE_LOCAL`, or the literal it stands for."""
    if isinstance(node, ast.Name):
        return node.id == "NODE_LOCAL"
    if isinstance(node, ast.Attribute):
        return node.attr == "NODE_LOCAL"
    return isinstance(node, ast.Constant) and node.value == "local"


def _calls_with_local_nick(source: str, func: str) -> int:
    """How many calls to ``func`` in ``source`` name the local nick."""
    count = 0
    for node in ast.walk(ast.parse(source)):
        if not isinstance(node, ast.Call):
            continue
        callee = node.func
        if isinstance(callee, ast.Attribute):
            name = callee.attr
        elif isinstance(callee, ast.Name):
            name = callee.id
        else:
            continue
        if name != func:
            continue
        nicks = [*node.args[:1], *(k.value for k in node.keywords if k.arg == "nick")]
        count += sum(_is_local_nick(n) for n in nicks)
    return count


def _modules_calling(func: str) -> set[str]:
    return {
        path.relative_to(_SRC).as_posix()
        for path in sorted(_SRC.rglob("*.py"))
        if _calls_with_local_nick(path.read_text(encoding="utf-8"), func)
    }

def test_serve_is_the_only_writer_of_the_local_snapshot():

# Shown once per picker run, on the first paint that had to sweep live because
# serve's snapshot was missing or stale. A hint, never an error: the picker
# keeps working with serve down -- it is just slower. ASCII only (psmux panes,
# legacy code pages).
_SERVE_HINT = "swept live: no fresh snapshot -- `magent serve` keeps one and makes this list instant"


@dataclass(frozen=True)
class _Listing:
    """What one paint lists, and where that answer came from."""

    sessions: list[str]
    age_s: float | None  # the snapshot's age; None = a live sweep answered
    fell_back: bool = False  # the snapshot was missing or stale


def _list_sessions(
    candidates: list[str],
    sweep: Callable[[], list[str]],
    *,
    live: bool,
    interval_s: float,
    now: float | None = None,
) -> _Listing:
    """The sessions one paint lists, from serve's snapshot when it can.

    ``live`` (the user pressed `r`, or the last attach failed) goes straight to
    ``sweep``. Otherwise a fresh snapshot is filtered to ``candidates`` -- in
    config order, so a row's number means what it did before, and never a
    session this config does not own (a serve on another config writes the
    same file). A snapshot listing NONE of them is not believed: empty may mean
    "nothing runs" or "serve reads another config", and only a live sweep may
    say the former. Missing or stale: sweep, and say it fell back.
    """
    if live:
        return _Listing(sweep(), None)
    snap = nodes.read_sessions(NODE_LOCAL)
    t = time.time() if now is None else now
    if snap is None or nodes.sessions_stale(snap, pull_interval_s=interval_s, now=t):
        return _Listing(sweep(), None, fell_back=True)
    known = set(snap.sessions)
    listed = [s for s in candidates if s in known]
    if not listed:
        return _Listing(sweep(), None)
    return _Listing(listed, max(0.0, t - snap.ts))


def _source_label(age_s: float | None) -> str:
    """The header's word on where the list came from."""
    return "(live)" if age_s is None else f"(snapshot {int(age_s)}s ago)"

def _run_sessions_picker(config_file: Path, name: str | None = None) -> None:
    """Looping psmux session picker: list sessions, attach to a choice, repeat.

    Each paint lists from serve's session snapshot while it is fresh and sweeps
    live otherwise (``_list_sessions``; the module docstring says why the list
    may be up to 20 s behind ``status``). A focus-target file (set by the upload
    server's /focus endpoint, e.g. from a notification tap) lets the
    currently-attached session be switched remotely: /focus detaches this
    picker's client, the attach returns, and the loop jumps straight to the
    requested project."""

    from magent import psmux as psmux_mod  # heavy subsystem: in-body per policy

    # sibling module: the one config -> staleness-window translation, shared with
    # the attention daemon / watch / status so no surface ages states differently.
    from magent.cli.attention_cmd import staleness_from_config

    # _running_upload_port below imports upload_server on every run anyway, so
    # reading the snapshot cadence from its owner costs nothing extra.
    from magent.upload_server import (
        SESSION_SNAPSHOT_INTERVAL_S,  # heavy subsystem: in-body per policy
    )

    psmux_bin = psmux_mod.find_psmux()
    if not psmux_bin:
        click.echo(
            f"  {style('x', fg='red')} psmux not found on PATH. Install: choco install psmux"
        )
        return

    # Candidates come from config, in config order -- liveness is NOT checked
    # here, so a direct-name attach never depends on a sweep. Each project's
    # resolved path rides along: it is the cwd magent created the session with,
    # which is what the agent-state lookup keys on.
    cfg = _load_config_or_exit(config_file)
    # Read once here rather than per paint: the windows cannot change under a
    # running picker, and every redraw must age states the same way.
    staleness = staleness_from_config(cfg)
    candidates: list[str] = []
    resolved: dict[str, str] = {}
    for proj in psmux_mod.eligible_projects(cfg):
        sid = psmux_mod.socket_id(proj)
        candidates.append(sid)
        path = proj.get("resolved")
        resolved[sid] = path if isinstance(path, str) else ""

    def _attach(target: str) -> None:
        _attach_session(psmux_bin, target, _reset_terminal)

    if name:
        matches = [s for s in candidates if name.lower() in s.lower()]
        if matches:
            _attach(matches[0])

    # Tappable from a phone SSH client: one tap opens the uploader, then Add to
    # Home Screen (iOS: tap to install the Web Clip profile). Shown only when a
    # live upload server is detected, so the link always works.
    port = _running_upload_port()
    upload_url = f"http://{_tailnet_host()}:{port}/" if port else None

    def _sweep() -> list[str]:
        # The one liveness enumeration -- the SAME call `status` and `down`
        # make, so a live paint can never list a session they would skip.
        return psmux_mod.live_sessions(candidates, psmux=psmux_bin)

    hint_shown = False
    while True:
        listing = _list_sessions(
            candidates, _sweep, live=False, interval_s=SESSION_SNAPSHOT_INTERVAL_S
        )
        sessions = listing.sessions
        if not sessions:
            # Only ever a LIVE answer: _list_sessions sweeps rather than trust an
            # empty snapshot, so a stale file can never say "nothing runs".
            click.echo(f"  {style('x', fg='red')} No active psmux sessions.")
            click.echo(
                f"  {style('Run', dim=True)} {style('magent up', bold=True)} {style('or', dim=True)} "
                f"{style('magent --go', bold=True)} {style('first.', dim=True)}"
            )
            return

        # Remote switch: a notification/web tap dropped a target here -> jump to it.
        focus = _consume_focus_target()
        if focus and focus in sessions:
            _attach(focus)
            continue

        hint = None
        if listing.fell_back and not hint_shown:
            hint, hint_shown = _SERVE_HINT, True
        statuses = _session_statuses(
            _session_cwds(psmux_bin, sessions, resolved), staleness
        )
        choice = _read_choice(
            _session_rows(sessions, statuses),
            upload_url,
            source=_source_label(listing.age_s),
            hint=hint,
        )
        if choice is None or choice == "q":
            return

        target = None
        try:
            idx = int(choice) - 1
            if 0 <= idx < len(sessions):
                target = sessions[idx]
        except ValueError:
            matches = [s for s in sessions if choice in s.lower()]
            if matches:
                target = matches[0]

        if target:
            _attach(target)
        else:
            click.echo(f"  {style('x', fg='red')} Invalid choice.")

````markdown
### The picker paints from a snapshot (2026-09-24)

**The session list is a file, and serve keeps it.** `magent sessions` -- and
every return to it with F1 -- used to sweep every configured psmux socket with
`has-session` on every paint: about 19 s for 46 sockets on a loaded host, paid
again each time an attach returned, and paid in full by every phone that opened
the picker over ssh, because each of those is a fresh process with nothing in
memory to reuse. `magent serve` is the one process that is always up on a real
box, so it is the writer: `_supervise_session_snapshot` sweeps once at start and
then every `SESSION_SNAPSHOT_INTERVAL_S` (10 s, measured start to start so a
slow sweep does not stretch the cadence), with the same `psmux.live_sessions`
call as always (through `discover_sessions` -- a cache of the one enumeration,
not a fourth sweep). `_refresh_sessions` writes the live names to
`~/.magent/nodes/local/sessions.json` in the node mirror's `{ts, sessions}`
shape, atomically, stamped when the sweep RETURNED (a start stamp on a 19 s
sweep would look nearly stale on arrival). The same sweep refreshes the phone
page's `/api/sessions` cache, so a request no longer sweeps inside its own
thread. `local` is a reserved node nick, so no pool machine can share that
directory. A failed write never costs the cache and is logged once per failure
streak.

**The picker is the only reader, because a snapshot may be 20 s behind.** It
lists from the file while `nodes.sessions_stale` says it is at most two
intervals old, filtered to its own config's sessions in config order (a serve
on another config writes the same file), and sweeps live when the file is
missing or stale (with one dim hint naming `magent serve`), when the user
presses `r`, or on the paint after an attach failed. A snapshot that names none
of its sessions is not believed, so "No active psmux sessions" is only ever said
after a live sweep. That lag is acceptable for a LIST and for nothing else: the
picker only offers rows, and a row that died since the snapshot costs one failed
attach, which is exactly what forces the next paint live. Everything that
decides a kill or reports the truth -- `status`, `down`, the menu,
`sessions --json` -- stays on the live sweep, and a second reader would be a
second answer to "which sessions are live", the drift the one-enumeration rule
exists to prevent.

**No env var.** The supervisor probes only the configured session names and
writes only under `~/.magent`, which every test fixture already redirects. It
reaches nothing outside HOME, and that is the test a `MAGENT_*` opt-out has to
pass to join `MAGENT_HOTKEY_SUPERVISOR`, `MAGENT_UPLOAD_SUPERVISOR`,
`MAGENT_PSMUX_BOOST` and `MAGENT_NODE_SYNC`.

Proof: `tests/unit/test_session_snapshot_readers.py` (an AST scan: the picker
is the only `read_sessions(NODE_LOCAL)` caller in `src/`, serve the only
`sessions_path(NODE_LOCAL)` caller), `tests/unit/test_session_picker.py::
TestThePickerPaintsFromTheSnapshot` (zero `live_sessions` calls on a fresh
snapshot, against a fake sweep that sleeps 2 s), and
`tests/e2e/test_session_snapshot.py` (a real serve writes a fake psmux's live
names within two intervals, then rewrites them).
````

````markdown
**The local session snapshot can go stale between writes (2026-09-24):**
`nodes.sessions_stale` calls the picker's snapshot stale at two
`SESSION_SNAPSHOT_INTERVAL_S` (20 s). The supervisor starts a sweep every 10 s,
but a sweep cannot start until the last one returned, so when one
`live_sessions` fan-out takes longer than about 20 s (the measured worst case
was ~19 s for 46 sockets) the file ages past stale between writes and the
picker falls back to a live sweep for part of every cycle. That is no worse
than before the snapshot, only not instant. The fix, if it bites, is for the
snapshot to carry its sweep's duration and the reader to widen its window by it.

**Every real-serve e2e tier now carries a `has-session` fan-out every 10 s
(2026-09-24):** any tier that runs a real `magent serve` over a fake `psmux`
(the Alt+V, serve-watchdog, spawn-no-console, browser, soak and
session-snapshot tiers) now also sees serve's snapshot supervisor probe every
configured session at start and every 10 s after. The tiers that assert on
recorded psmux calls filter by argv, so the probes are invisible to them, with
one soft spot: `tests/e2e/test_spawn_no_console.py`'s `_await_records(
at_least=4)` wait can be satisfied early by supervisor records. Its presence
assertions still require the flash and `send-keys` records, so an early wake
is a shorter wait, not a false pass. Not observed as a failure; recorded so a
new flake or latency regression in those tiers is checked against it first.
There is deliberately no env opt-out (see §2 "The picker paints from a
snapshot"); a tier that needs silence gives its serve a config with no
psmux-eligible project.
````
